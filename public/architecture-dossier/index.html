System Architecture Dossier

PROVA

Denied-Party Screening & Compliance Platform

PROVA screens counterparties — organizations, individuals, vessels, aircraft — against global sanctions and PEP lists, then carries whatever it finds through investigation, decision, and audit. The six exhibits below take the platform apart at six different seams: the physical machines it runs on, the domain layers that organize its logic, the pattern enforced inside every one of its 29 microservices, the event backbone that connects them, the exact path one screening request takes from browser to verdict, and the safeguard that keeps an AI agent from ever acting on its own.

A

Hardware & Deployment Topology

Seven purpose-built Proxmox VMs on a home lab network — nothing runs on the laptop that writes the code.

Every VM has a static address pinned in two independent places, so a reboot can't silently hand a service a new address. Public traffic reaches this same core box through DNS and a firewall NAT rule, terminating TLS at Traefik rather than at the edge.

H

Performance & Concurrency, Measured

Three questions — pool depth, cache placement, thread behavior — answered by instrumenting the lab rather than guessing, plus an honest ledger of what's still on the default.

Kafka listener concurrency
default
No service sets concurrency= — every @KafkaListener processes its topic's partitions on a single thread, everywhere on the platform.
@Async executor
default
reporting-service and batch-screening-service use @Async with no custom TaskExecutor bean, so both fall back to Spring's SimpleAsyncTaskExecutor — unbounded, unpooled, one raw thread per call.
Java 21 virtual threads
not adopted
spring.threads.virtual.enabled is unset platform-wide, despite every service running on Java 21.
Cross-worker outbox concurrency
deliberate
PostgresSkipLockedOutboxClaim — a FOR UPDATE SKIP LOCKED query — lets multiple outbox-relay ticks claim rows without blocking each other. The one place concurrency safety was engineered on purpose, and it's done at the Postgres layer, not the JVM.

K

Technology Choices & Trade-offs

What was picked, what was turned down, and why — pulled from the platform's own ADRs rather than reconstructed after the fact.

DecisionChosenRejected alternativeWhySource
AI agent tier language Python + FastAPI, standalone services Spring AI / in-JVM Java agents "Convention over merit" — Python is the AI-mainstream ecosystem and yields a cleaner polyglot boundary than bolting agents onto the Spring monorepo. ADR-0035
Agent orchestration Hand-rolled loop + LiteLLM under a model-agnostic LlmPort LangChain A heavyweight framework "reintroduces the framework lock-in this decision exists to avoid, and obscures the learning goal." ADR-0035 §2
LLM hosting Ollama, local on ml (open-weight, 7–8B) Hosted-LLM-first (Claude / OpenAI) Rejected on cost and data residency for a compliance product handling counterparty PII; kept as a drop-in LlmPort adapter for a later premium tier. ADR-0035 §6
Multi-tenancy model Keycloak Organizations, single realm Realm-per-tenant "The operational cost of one Keycloak realm per individual-tier customer is absurd — N realms for hundreds of single-user accounts." Hard cryptographic isolation isn't what mid-market exporters ask for. ADR-0019
Service-internal structure Hexagonal/DDD, ArchUnit-enforced (Exhibit C) Convention-only layering, trusted to code review Six ArchUnit rules run in CI on every service so the boundary can't erode one unreviewed PR at a time. CLAUDE.md
Event streaming Redpanda Upstream Apache Kafka Kafka-wire-compatible — every client library, config, and topic convention carries over unchanged — with a lighter footprint appropriate to a single-VM lab deployment. A pragmatic pick, not a numbered ADR. CLAUDE.md
Fuzzy name matching OpenSearch + Beider-Morse phonetic analyzer Exact / token-overlap matching only Catches transliteration variants exact matching misses — "Wladimir" ↔ "Vladimir" — by encoding phonetic variants across all-languages, generic name-type rules. CLAUDE.md
Data ownership One Postgres schema per service, zero cross-service reads Shared database / shared schema A schema change in one service can never silently break another — the API or an event is the only contract between them. CLAUDE.md

Three of eight rows cite CLAUDE.md rather than a numbered ADR — that's an honest distinction, not a gap filled in after the fact. Formally-ADR'd decisions went through an explicit alternatives-considered process; the CLAUDE.md rows are equally deliberate but were codified directly as platform rules rather than routed through the ADR process.
